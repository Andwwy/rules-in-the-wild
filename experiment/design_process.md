## The pilot's translation (superseded)

The translation was done once, before the runs. At run time there is no translation phase: the two arms are two
parallel universes (point 21), the same task run in two environments, one of which has the rules enforced at system level.

1. **The translation, before the runs** (point 15; point 21: no phase 0 at run time). The translator wrote each task's
   enforcement once, offline: for each
   policy rule, from the rule's enforcer-tree mapping, the enforcer (a concrete component in the mapped class), its
   **config** (the enforcer's own configuration file), its **target** (what it checks: `reply`, the turn's final reply;
   `code-file`, a code file, and at the end of the turn every code file of the project; `any-file`, any file's path, and
   at the end of the turn the project tree) and its **triggers** (when it runs, below). Building the task's steered

2. **The runs.** Each arm runs the task the same way. In the steered arm the enforcement acts by itself, at its

## The pilot's threats to validity (superseded)

| | |
|---|---|
| The steered environment | The steered image also holds node (and Semgrep in tasks 46, 51, 91) in `/opt/enforce`; MTAC's default image has no node. The agent can find and use them; they are part of the steered universe (point 21) |
| Reminders, not only enforcement | Each block puts the rule text and a fix instruction into the conversation and adds agent iterations. A steered > base result can come from these reminders and not from the deterministic checks. `compare_arms.py` reports the enforcement verdicts per task; a reminder-only arm would separate the two later |
| Circularity (measured) | The enforcers and MTAC's checkers check the same rules, so the outcome partly measures how close the translator's reading of each rule is to the checker's. Measured after the runs (`scripts/agreement.mjs`, no model calls) on the steered arm (the base arm has no enforcer, point 28): each scored rule's own enforcer on the same saved replies and end-of-turn workspaces that MTAC's checkers scored. They agree in 298 of 314 rule-turns. All 16 disagreements are our enforcer passing what MTAC's checker failed: 51-8 odd line count (9 of 9 turns), 46-5 two spaces around `=` (5 of 10), 46-6 function names (1), 46-8 odd file-name length (1). These are translation mismatches (point 27: accepted, and marked on the results page and in `reports/`); for 51-8 the enforcement steered the agent towards files that MTAC's checker fails. Why each one differs was not traced: that needs reading the checkers, which the translator does not do. Where MTAC's checker found each violation is found black-box (point 28, `scripts/mtac_locate.py`: the checker run again on reduced copies of the material) and shown on the results page |
| Leakage | The session that translated also built the task folders, which hold MTAC's `validation_code` (`tasks/*/data/questions.jsonl`), and `../task data/checkers/` was readable from it; `rules.json` shows which rules are scored. The rule "checker scripts are never used, read or copied for the enforcement" was followed, but this access cannot be ruled out from the files |
| Sample | The tasks were chosen because their rules can be checked by script, so they favour regex-friendly rules. With 5 pairs, 1 run and a binary C-ISR, each band has about 10 turn-level points per arm: descriptive only |
| Rigid enforcement | The enforcement always enforces `CLAUDE.md` as written (point 24). When a later turn's user instruction changes a policy rule, the steered agent still gets the enforcer's feedback for the original rule and handles the conflict itself; the base agent sees only the conflicting instructions. This inflexibility is part of the treatment, and its cost shows in the scores of such turns |
| Silent failure | Fail open on an enforcer error, the block cap, a skipped rule at the hook's time limit, and Semgrep errors all let actions through; each is in the enforcement log, which a null result must be read with |
| Asymmetries | An AgentProbe restart in one arm only (recorded). The judge fallback sees the steered arm's enforcement messages. The agent runs as root and can read or edit `/opt/enforce` and `/etc/claude-code`: search the traces for both paths. The enforcement's English messages inside a Chinese session can affect the "reply only in Chinese" rules |
